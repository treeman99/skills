# 승격 후보

코디네이터가 `worker_done` 이후 사용자 지적을 받거나, 실행 도중 `rules.md`에 없던 프로젝트 요구를
받으면 여기에 **한 건씩** 자동으로 적는다. 승인은 필요 없다 — 이 파일은 어떤 워커의 컨텍스트에도
들어가지 않으므로 틀린 후보가 쌓여도 실행 비용이 0이다. 이번 산출물에 대한 일회성 취향은 규칙이
아니므로 적지 않는다.

승격은 사람이 결정한다. **관측 2회** 이상이거나 사용자가 명시적으로 요청했을 때만 `rules.md` 승격을
제안하고, 다음 중 하나에 해당하면 제안하지 않는다.

- 이 프로젝트의 lint·typecheck·테스트가 이미 잡는다 → 기각
- 기존 블록과 `scope`가 겹친다 → 병합안으로 제시
- 이 머신에서만 참인 사실이다 → 세션 메모리로 보내고 커밋하지 않는다

승격 심사는 한 run의 마지막 워커가 정산된 뒤에 묻고, 다음 run이 `rules.md`를 읽는 시점에 미결
후보를 다시 확인한다.

형식은 아래와 같다. 요약이 아니라 **다음 워커가 실행할 지시**로 쓴다.

```text
### C-00N · scope: <scope> · 관측 N회 · YYYY-MM-DD
<다음 워커가 해야 할 일 한 문단>
출처: <task_id> worker_done 직후 사용자 지적
```
